# Separate the work surface from the model

Last verified: 2026-09-28

ChatGPT is the conversational surface. Work is intended for longer deliverables and connected multi-step work; Codex emphasizes code, repositories and tests. Those are workflow distinctions, not proof that any particular surface/model is enabled in this account. A long task alone does not require moving out of chat if the needed tools already work there.

An API model ID, a ChatGPT selector label, and a Pro subscription are different things. Do not derive an API slug from a visible label or assume subscription usage pays an API invoice. Check actual runtime tools, the installed client's model list and the user's enabled plan/workspace features before relying on them. A successful invocation is evidence about that session, not universal availability.

When a task crosses surfaces, carry the artifact, source locations, decisions, unresolved gaps, permissions and tests. Do not claim that another product can see the current Project's private conversation. Account settings, a local checkout and a downloaded skill are not automatically the same state.

Work/Codex usage and feature availability may differ from ordinary chat and change over time. This pack stores no account quotas. Missing model/tool access is a routing constraint, not a reason to simulate the action in prose.
