# Source and freshness policy

Last verified: 2026-09-28

Use first-party model/endpoint pages for technical constraints, Help Center for the exact ChatGPT surface, and Academy for methods and learning sequence. Compare publication/update dates and retrieval coverage, not merely the domain. An older illustrative model in an Academy lesson or reasoning tutorial is not a current recommendation.

Volatile facts include IDs, prices, quotas, availability, tool support, reasoning/mode values, client commands, config locations and deprecations. Verify the exact claim live before treating it as current. Stable methods may be used without an extra browse. If live retrieval fails, say which fact remains uncertain and keep the existing verified content; do not fill gaps from an announcement headline.

The initial index/direct-body disagreement for GPT-6 is recorded in models.md. Search-index text is evidence with an access limitation, not equivalent to reading the whole live page. Watcher hashes establish retrieval, not semantic verification. Never advance Last verified based on a successful hash check alone.

New models enter the register as unmeasured candidates. Retirement needs an explicit first-party notice for the relevant surface. Existing models can remain useful for compatibility or cost. New announcements should prompt evaluation, not automatic replacement.
